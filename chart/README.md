# OpenLDAP Helm chart

Deploys the Bitnami-compatible OpenLDAP 2.7 image (`ghcr.io/genesary/openldap`) on Kubernetes.
The chart follows Bitnami's chart conventions and builds on Bitnami's
[`common`](https://github.com/bitnami/charts/tree/main/bitnami/common) library chart.

## Installing

```sh
helm dependency build .
helm install my-ldap . --namespace ldap --create-namespace
```

Retrieve the generated admin password:

```sh
kubectl get secret -n ldap my-ldap-openldap -o jsonpath='{.data.admin-password}' | base64 -d
```

## Highlights

- StatefulSet with one PVC per replica mounted at `/bitnami/openldap`.
- Credentials are kept in a Secret and reused across upgrades. Unset passwords are generated
  randomly. `auth.existingSecret` lets you supply your own; it must contain the keys listed in
  `auth.secretKeys`.
- TLS via `tls.enabled`. It uses either an existing secret or a self-signed CA and certificate
  generated by the chart.
- Custom LDIF files (`customLdifFiles`) and schemas (`customSchemaFiles`) are mounted at `/ldifs`
  and `/schemas`.
- Access log, syncprov, ppolicy and PROXY protocol support are exposed under `ldap.*`.

See [Parameters](#parameters) for the full list.

## Caveats

- **Settings apply only at first boot.** The image only bootstraps the directory (credentials,
  default tree, LDIF and schema files) when the data volume is empty. Changing these values later
  does not update an existing directory.
- **`runAsGroup` must stay `0`.** The image grants `cn=config` access over `ldapi://` to
  `gidNumber=0+uidNumber=<uid>`. With any other GID, the first boot fails with
  `OpenLDAP failed to start`.
- **Keep the `NET_BIND_SERVICE` capability.** `slapd` (and its `slap*` aliases) carries the
  `cap_net_bind_service` file capability. Without that capability in the bounding set, the kernel
  refuses to execute it (`Operation not permitted`).
- **Replicas do not share data by themselves.** `replicaCount > 1` only runs independent
  servers. Replication needs a syncrepl configuration, for example provided through
  `customLdifFiles` together with `ldap.syncprov.enabled`.
